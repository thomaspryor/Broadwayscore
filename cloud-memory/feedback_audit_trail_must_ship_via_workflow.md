When adding an audit/admin JSON that's regenerated by `rebuild-all-reviews.js` and read at SSR time from `process.cwd()/public/data/...`, the file must be `git add`'d in BOTH `.github/workflows/rebuild-fast.yml` AND `.github/workflows/rebuild-reviews.yml` commit blocks.

**Why:** Both workflows have an explicit allow-list of paths to stage (`git add public/opening-night-status.json`, `git add public/data/shows/`, etc.), not a blanket `git add public/`. A new path is invisible to git until added. The rebuild logs `🔒 Locks index: 217 locks` and exits successfully, so CI is green — but on Vercel, the page reads from a stale or non-existent file because the regeneration never landed in the public repo.

**How to apply:** When wiring a new step into `rebuild-all-reviews.js` that writes to `public/data/...`, immediately update both workflow files. Confirm via `gh run view --log | grep "git add public/data/admin"` that the staging line fires.

Caught in /ship-check (P0 #1) on the locks-index feature 2026-04-27. Fix was a 2-line addition each in `rebuild-fast.yml:171` and `rebuild-reviews.yml:329`.
