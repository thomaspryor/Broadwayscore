When you `git worktree add` on `~/BroadwayScorecard-app/` (the iOS Expo app), the worktree gets a clean checkout but **does not get node_modules**. Running `npx tsc`, `npx tsx`, or `npm run lint` in the worktree will fail with cryptic errors:

- `npx tsc` → installs the wrong tsc@2.0.4 package and prints "This is not the tsc command you are looking for"
- Without TS lib config: cascade of `Cannot find name 'Set' / 'Map' / 'Promise' / 'process'` errors
- `tsconfig.json` references `expo/tsconfig.base` from node_modules which doesn't exist
- `npm run lint` may also misbehave

**Fix:**
```bash
cd ~/BroadwayScorecard-app-MY-WORKTREE && /bin/ln -sf ~/BroadwayScorecard-app/node_modules ./node_modules
# then run checks using main repo's binaries:
~/BroadwayScorecard-app/node_modules/.bin/tsc --noEmit -p .
~/BroadwayScorecard-app/node_modules/.bin/tsx scripts/test-ticket-tracking.ts
# remove before commit (gitignored, but be explicit):
/bin/rm node_modules
```

**Why:** `npm install` in every worktree would burn ~3 min and ~600MB. Symlink is instant and node_modules is gitignored.

**For `expo export` specifically (bundle verification):** the bundler needs a real working directory with node_modules + lockfile. Symlink alone may not be enough. Workaround: `cp` the worktree's edited files into the main repo, run `npx expo export` from the main repo, restore main's files with `cp` afterward. Verify with `git status` that the working tree is clean before committing the worktree branch.

**Don't run `npm install` in the worktree** — it'll generate a duplicate package-lock.json that drifts from main and may even modify dependencies if the registry has updates. Symlink is the only safe path.

**Caught:** twice in 2026-04-25 session while wiring TodayTix affiliate URLs into the iOS app — once for the initial wiring (commit e164e29), once for the Linking.openURL handoff fix (commit a48b1ed). Same trick worked both times.
