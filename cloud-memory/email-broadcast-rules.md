Full incident history and architecture migrated to Notion. See [Email Broadcast Safety Rules](https://www.notion.so/330637c5416f8163ae09d04e92b7eb16) under BWSC.

**Rules still enforced here (Claude must follow regardless of Notion):**
- NEVER call `POST /broadcasts/{id}/send` — code only creates Resend DRAFTS. Owner clicks Send manually.
- NEVER touch subscriber lists (no import, add, remove, modify)
- For testing: `--send-to=your@email.com` (transactional, never broadcast)
- Any subscriber request: show command, stop. User runs manually.

**When a draft has bugs and needs to be recreated:**
- Use `--recreate-draft` flag: deletes old Resend draft via API, clears completed flag in opening-night-sent.json, creates fresh draft
- Do NOT manually edit opening-night-sent.json — use the flag instead
- The draft script (send-opening-night-broadcast.js) is the ONLY code path for creating drafts

**When consensus text is missing from draft:**
- Script warns but doesn't block — email sends without Critics' Take section
- Once critic-consensus.json is generated, run `--recreate-draft` to replace with complete version
- Consensus is generated by update-critic-consensus.yml — may lag opening night by hours

## `create_draft` (formerly `send_to_all`) only creates a draft (2026-08-26, renamed BRO-2440 2026-10-13)

The input is now `create_draft`; `send_to_all` remains a deprecated alias with
the same behaviour. Neither sends to subscribers.

`opening-night-broadcast.yml`'s `send_to_all` input does NOT send to the
audience. It sets `--send-to=$OWNER_EMAIL` (a transactional preview to the
owner) plus `CREATE_DRAFT=true`. No audience send happens on that path.

**A plain `gh workflow run opening-night-broadcast.yml` with default inputs
produces NO draft unless a pending show is past its draft deadline.**
`CREATE_DRAFT` starts `false` and flips true only on `create_draft == true`
(or its alias `send_to_all`), on the `30 12 * * *` cron (NOT the hourly
`41 13-23` cron), or in deadline mode (BRO-4417: a pending show past 14:00 UTC
the day after opening, on any trigger). Otherwise a default dispatch takes the
else branch: owner preview only. `send_to=<email>` wins over `create_draft`
(preview to that address, no draft). Past-deadline shows get
`--force-create-draft` in every draft mode.

This cost two sessions three failed dispatch attempts on Paranormal Activity,
and produced a handoff doc that told the next session to use default inputs AND
to avoid `send_to_all` — an instruction that guaranteed the deliverable could
never appear.

**How to actually create an opening-night draft:**
- Fastest and CI-independent: `node scripts/send-opening-night-broadcast.js
  --market=broadway --lookback=2 --shows=<show-id>` (add `--dry-run` first).
  This is the sanctioned wrapper named by CLAUDE.md rule 17.
- Via CI: dispatch with `create_draft=true`. Safe — verified the script's only
  Resend endpoints are `/emails`, `POST /broadcasts`, and `DELETE
  /broadcasts/{id}` under `--recreate-draft`. There is no `/broadcasts/{id}/send`
  call anywhere in it; both greps matching it are comments.

Renamed in BRO-2440. The old one-click `/api/approve-broadcast` page was removed
in BRO-5256 (owner decision 2026-10-13): nothing minted its signed links, it never
dispatched (GitHub rejected its inputs), and it was a public GET with no
confirmation step. Any future one-click approval must be rebuilt with an explicit
confirmation step, not revived from git history.

## Policy: unsent opening-night drafts (BRO-2935, owner decision 2026-10-11)

Three July West End drafts (To Kill a Mockingbird, Jesus Christ Superstar,
Trainspotting) sat unsent in Resend for months. Nothing flagged them because a
draft looks "handled" to every tracker check. Policy:

- An opening-night draft nobody sends gets DELETED, never sent late. Use
  `discard-broadcast-draft.yml` (dry run by default; `dry_run=false` to act).
  It refuses unless every tracker record of the draft is unsent, every show of
  a combo draft is named, and a live Resend GET says `draft`. It never calls
  `/send`.
- Discarded records keep their history and get `discardedAt`
  (`markDraftDiscarded` in `scripts/lib/broadcast-state.js`). Every consumer
  treats them as resolved: the send filter, deadline re-queue, reconcile,
  missed-broadcast check and recreate guard all skip them. `discardedAt` is a
  recency field, so a stale tracker copy cannot resurrect the draft on merge.
- `check-missed-broadcasts.js` (daily, data-health-check.yml) pages one
  `broadcast:draft-unsent:<draftId>` alert per draft that is 3 to 30 days old
  and still `draft` on a live GET, skipping shows already in a never-sent alert.
