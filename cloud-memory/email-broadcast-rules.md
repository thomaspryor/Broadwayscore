Full incident history and architecture migrated to Notion. See [Email Broadcast Safety Rules](https://www.notion.so/330637c5416f8163ae09d04e92b7eb16) under BWSC.

**Rules still enforced here (Claude must follow regardless of Notion):**
- NEVER call `POST /broadcasts/{id}/send` — code only creates Resend DRAFTS. Owner clicks Send manually.
- NEVER touch subscriber lists (no import, add, remove, modify)
- For testing: `--send-to=your@email.com` (transactional, never broadcast)
- Any subscriber request: show command, stop. User runs manually.

**When a draft has bugs and needs to be recreated:**
- Use `--recreate-draft` flag: deletes old Resend draft via API, clears completed flag in opening-night-sent.json, creates fresh draft
- Do NOT manually edit opening-night-sent.json — use the flag instead
- The draft script (send-opening-night-broadcast.js) is the ONLY code path for creating drafts

**When consensus text is missing from draft:**
- Script warns but doesn't block — email sends without Critics' Take section
- Once critic-consensus.json is generated, run `--recreate-draft` to replace with complete version
- Consensus is generated by update-critic-consensus.yml — may lag opening night by hours
