When `vercel-deploy.yml` deploys a code-only change (no data files modified), it sets `SKIP_HEAVY_PREBUILD=true`. This skips `generate-mobile-show-details.js`, `generate-mobile-data.js`, and `generate-homepage-archive.js` in `prebuild.sh`. The committed public/data/shows/*.json files from git are used as-is.

Meanwhile, the show page still renders fresh from `engine.ts` using the reviews.json checked out via `checkout-core-data`. So the show page uses the latest scoring formula on the latest data, but the public JSON uses whatever was last committed.

**Why:** After the multi-critic dedup fix (commit accdbbb333, April 11, 2026) changed engine.ts + compute-critic-score.js, subsequent code-only deploys served public JSONs generated by the OLD outlet-level dedup (committed before the fix), while show pages used the NEW critic-level dedup. Result: 0.1-0.7 point drift across 441 shows, some crossing rounding boundaries.

**How to apply:** After ANY commit that changes the scoring formula in engine.ts or compute-critic-score.js, ALWAYS trigger a fast rebuild (`gh workflow run "Rebuild Reviews (Fast)"`) even if the deploy was code-only. The rebuild regenerates and commits the public show JSONs with the new formula, closing the drift window.

**Longer-term fix:** Consider always running `generate-mobile-show-details.js` during prebuild regardless of SKIP_HEAVY_PREBUILD. It adds ~30s to code-only builds but prevents this class of drift entirely. The skip optimization was added to save ~1-2 min on code-only deploys; the 30s portion from mobile-show-details is a small subset.
