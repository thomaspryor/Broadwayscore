Some outlet pages (WhatsOnStage `/news/...review_XXXXX`, The Times) have an author list / non-deterministic byline area, so re-scrapes of the SAME review URL extract a DIFFERENT critic name each time. Review files are named `<outlet>--<slug(criticName)>.json`, so each variant is a NEW file → one URL accumulates as 9 same-body files. The write-guard marks them url-collision duplicates (circular `duplicateOf`), the real review's body gets classified `invalid`, and it never scores. This buried WhatsOnStage/Times reviews on both 2026 "A Midsummer Night's Dream" productions and Much Ado (Globe).

**Why:** `findExistingReviewFile` (scripts/lib/review-normalization.js) matched only by `(outlet, criticName)` — a URL is a review's identity, but it wasn't used.

**How to apply:**
- Detector: `node scripts/audit-review-url-clusters.js` flags any URL scraped into 5+ byline files (runs non-blocking in check-corpus-drift.yml). `findUrlClusters()` in scripts/lib/review-url-clusters.js.
- Root-cause fix (commit 9484a116b7): `findExistingReviewFile(showDir, outlet, critic, url)` Pass 0 matches by `canonicalReviewUrl` **within the same outlet** before criticName, so re-scrapes merge instead of spawning variants. The same-outlet gate is REQUIRED — aggregator roundup URLs (WET/Show-Score/Stagedoor) are legitimately shared across Telegraph/FT/Guardian star-stubs; URL-alone would collapse distinct reviews (see [[feedback_aggregator_roundup_urls_shared_across_outlets]]).
- **Do NOT hand-recover an already-exploded review.** It's a multi-flag whack-a-mole: write-guard re-marks the canonical as a dup → `contentTier:invalid` → `manualContentTier:complete` overridden on the junk body → `wrongShow:true` mis-flag. Needs the full 8-field manual-clear ([[feedback_manual_review_protection_fields]]); rarely worth it for one review. Existing clusters are a MIX of correct + wrong-production files (2024/2025 siblings) and can't be safely bulk-collapsed — /second-opinion killed a general `--fix` for this. Cleanup is per-show manual (Notion 393637c5-416f-8130).
- `canonicalReviewUrl` strips query/hash/slash; the write-guard's `normalizeUrl` keeps query — intentional divergence, the URL-dedup path is deliberately stronger.
- review-normalization.js is a score-source file → run scoring-delta + temporal regression before any edit ([[feedback_scoring_delta_required]]).

**Durability — collapsing existing clusters does NOT stick on its own (2026-07-05, Notion 394637c5).** After a `--fix` collapse, automation re-exploded the clusters within ~1h via two paths the `findExistingReviewFile` fix (9484a116b7) did NOT cover, both now fixed:
- `checkUrlCollision` (review-write-guard.js) marked the re-written file `duplicateOf` the FIRST same-URL sibling in readdir order — burying the real review under an empty stub (sarah-crompton→alun-hood) and wiping the `duplicateClearReason` breadcrumb. Fixed with `shouldMarkUrlCollisionDuplicate(newData, colliderData)`: keep the substantive-body file (fullText≥500) PRIMARY when the collider is (near-)empty (<200). Empty-vs-empty and equal-substance still defer to collider (historical). Multiple copies with IDENTICAL real bodies (byline explosion) still circular-shuffle, but circular-dup-recovery scores the real review once — SCORING is stable even when the audit's primaryCount cosmetically re-flags.
- `wrongProductionAutoCleared` "UK URL on London show" (rebuild-all-reviews.js ~2189) AND its WE/OB URL-year cousin (~1960) re-cleared `wrongProduction` on a `whatsonstage.com/shows/` **aggregate LISTING page** stub (4/5 star, empty body) → re-scored 80 as a WhatsOnStage double. Gated both on `!isShowListingUrl` (`/(whatsonstage|broadwayworld)\.com\/shows?\//` OR `isEvergreenListingUrl`; the latter needs a `-tickets` suffix so the bare-`/shows/` regex is load-bearing, not redundant).
- Lesson: a historical `--fix` is FUTILE until the write-guard/rebuild re-explosion paths are fixed AND deployed first. The corpus churns continuously (100s of commits/hr) — reset-to-origin + re-run the deterministic `--fix` rather than rebasing a collapse commit (conflicts on churned files). Both files are on the scoring watchlist → scoring-delta + temporal ([[feedback_scoring_delta_required]]).
- `--fix` remediation IS safe now (contra line 17's "per-show manual" note): `decideClusterAction` (scripts/lib/cluster-canonical.js) validates per-file via body + venue-match + verifyAggregatorUrl hardReject, uses a NARROW recovery field-set (never `operatorTrust:true` blanket immunity — ship-check caught that), pins/never-buries `humanReviewScore` files, and is idempotent (`primaryCount===1` = resolved, `--force` to reprocess).
- Follow-up: whatsonstage `/shows/` aggregate listing pages get ingested as reviews and score (separate class); moulin-rouge-we-2021 Chicago-tour `herbert-paine` stub scores via circular-dup-recovery (pre-existing wrong-production, T3).
