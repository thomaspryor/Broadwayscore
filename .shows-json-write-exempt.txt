# Allowlist for the shows.json direct-write lint (test.yml / pre-push).
#
# Format: one line per script: filename followed by `--` and a one-line reason.
# Lines starting with `#` are comments. Trailing whitespace is trimmed.
#
# Background: `data/shows.json` used to be written by 50+ scripts each doing
# their own fs.readFileSync/fs.writeFileSync pair with no coordination —
# concurrent writers could silently clobber each other's changes (see the
# "shows.json concurrency lock" card). All writers now route through
# scripts/lib/shows-write-guard.js, which adds a file lock plus a
# re-read-and-merge-by-id step before writing.
#
# New scripts cannot join this list — the lint blocks them. Only add an
# entry here for a script that genuinely writes a DIFFERENT shows.json-shaped
# file (e.g. a scratch/checkout copy outside data/shows.json) where the lock
# wouldn't apply anyway, with a one-line reason.
autonomous-merge-core-data-guard.test.mjs -- writes a data/shows.json inside its OWN mkdtemp throwaway git repo, never the real one; the fixture uses the real basename on purpose because the assertion is that UNTRACKED core-data files are left alone by cleanCoreDataTree
