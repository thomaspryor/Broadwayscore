# Pending-fix plan actions

Reference for hand-written `data/pending-fixes/bro-N.json` plans, the CI route for private-data fixes from cloud (BRO-4216; flow in `.claude/CLOUD.md` § Fixing private data). For plain field edits use `node scripts/new-fix-plan.js`, which fills `oldValue`, splits at 25 actions and runs preflight; its `--actions=<file.json>` takes any action below and fills `oldValue` where absent.

To withdraw an obsolete pending, partial, or validation-failed plan after checking current data, set `status: "superseded"`, `supersededAt` (ISO date), and `supersededReason` (the evidence and owning card). Preserve its identity and original plan, including actions. The executor skips superseded plans; this does not claim that any action ran. Do not hand-write `applied` or `rejected`, which are CI outcomes. A stale unresolved plan still needing work must remain unresolved.

A plan file is `data/pending-fixes/bro-N.json`: `issueNumber: "bro-N"`, fresh `planId` (uuid), `status: "pending"`, `submitter: {name: null, email: null}`, `plan: {summary, steps, riskLevel, actions}`. Actions:
- review text field: `{type: "review-field-edit", file: "<showId>/<file>.json", field, oldValue, newValue, description}`. Allowlist in `scripts/lib/review-field-edit.js`; `oldValue` must equal the current value. `scoreProvenance`: write `"page-parsed"` only, on a body-less file whose `scoreSource` is an LLM method label (BRO-6052); name the pre-relabel source recovered from review-texts history in `description`. `aggregatorStars`: clear only (`newValue: null`), only stars with no `aggregatorStarsSource`, and it queues the file for a rescore (BRO-6018). `url` only as a repair (BRO-4430): the current url must be an aggregator/round-up page, a non-review page, or another critic's review a sibling file holds; `newValue` is the outlet's own review url or `""` for an aggregator url on a Theatre Record text. Moves/deletes: `{type: "review-file-op", operation: "delete"|"move", sourcePath, destPath}`. Bring back a deleted file (text stays out of the plan): `{type: "review-file-op", operation: "restore", sourcePath, fromCommit: "<40-char review-texts sha>[^]", destPath?}` (`scripts/lib/review-file-restore.js`).
- shows.json / commercial.json field: `{type: "data-edit", ...}` (allowlist `scripts/lib/feedback-pipeline-fields.js`; commercial `showSlug` is the shows.json slug; absent field → `oldValue: null`).
- new commercial.json entry for a Broadway show with none: `{type: "add-commercial-entry", slug: "<shows.json slug>", entry: {designation, sources: [{type, url, date}], ...}}` (`scripts/lib/commercial-entry-action.js`: slug-keyed only, cited sources required, same per-record checks as validate-data.js; a non-TBD outcome is stamped `humanReviewedDesignation`). Model: `data/pending-fixes/bro-4627.json`.
- remove a junk or duplicate row: `{type: "retire-show", id, expectTitle, reason, blockTitleVenue?, duplicateOf?}` (`scripts/lib/retire-show-action.js`: only `provisional: true` rows, or with `duplicateOf` a same-title same-house duplicate with zero reviews (id-only), or with `nonProduction: true` + `evidenceUrl` (https venue listing) an announced/upcoming never-opened row with zero reviews, e.g. a cinema screening or one-night event (BRO-4449); `expectTitle` must match; writes the retired-id registry + archive; `blockTitleVenue: true` only for junk that must never return under any id, never for a duplicate). Model: `data/pending-fixes/bro-4398.json`.
- drop a stale audience-buzz key: `{type: "drop-orphan-key", file: "audience-buzz.json", showId, reason, renameTo?}`.
- flip an outlet's standing-coverage flag in `data/outlet-registry.json` (clears "Quality: standingCoverage drift"): `{type: "outlet-registry-flag", outletId, flag: "standingCoverage", value: true|false, reason}` (`scripts/lib/outlet-registry-flag-action.js`: refuses unless `node scripts/audit-standing-coverage.js` lists the outlet under promote (true) or demote (false) at execute time, so a plan can go stale; already at the target value is an ok no-op; promote also writes `standingMarkets: ["broadway"]`, demote removes both fields; BRO-6122). Model: `data/pending-fixes/bro-6115.json`.
- refresh a decayed `coverageExpectation: "reviews"` claim in `data/outlet-registry.json` (clears "Quality: coverageExpectation drift", every 14 days; BRO-6610): `{type: "coverage-expectation-redecide", outletId, reason}` (`scripts/lib/coverage-expectation-redecide-action.js`: re-measures at execute time, stamps `coverageExpectationDecidedAt` with today and appends the measured rate to `coverageEvidence`; ok no-op when already active; refuses a `none`/no-review claim, a contradicted or no-evidence outlet, which need a human re-decision). Plan with one action per id listed by `node scripts/audit-standing-coverage.js --coverage-expectation`.
- clear an "outlet domain moves" digest row in `data/outlet-registry.json` (BRO-6632): `{type: "outlet-registry-alias", outletId, host, kind: "domainAlias"|"notDomainMove", reason}` (`scripts/lib/outlet-registry-alias-action.js`: `domainAlias` = the host is that outlet, appended to `domainAliases`; `notDomainMove` = checked, a different paper, appended to `notDomainMoves`. Host must be bare and slug-match the outlet's `domain`; refuses a host another outlet owns or one recorded under the opposite kind; already present is an ok no-op).
- cosmetic title repair (case, punctuation, a trailing slug counter; id/slug unchanged): `{type: "retitle-show", id, expectTitle, newTitle, reason}` (`scripts/lib/retitle-show-action.js`). Model: `data/pending-fixes/bro-4505.json`.
- new shows.json entry: `{type: "add-show", show: {...}, crossLinkFrom?}` (`scripts/lib/add-show-action.js`: refuses an existing id/slug, placeholder venues and unknown fields; `crossLinkFrom` also appends a `priorRuns` link on that existing show; `priorRunOf: "<earlier run id>"` instead puts the link on the NEW entry, for a return engagement). Same-title reruns: `<slug>-off-broadway-<year>`. Art in `public/images/shows/<id>/` lands with the plan. Model: `data/pending-fixes/bro-4259.json`. Then dispatch `gather-reviews.yml` with `shows=<id>`.
- a review page CI runners can't fetch (blocks GitHub IPs, e.g. Bachtrack) but a cloud session can (BRO-5886): `node scripts/make-html-handoff-plan.js --plan=bro-N --show=<id> --url=<review url> [--outlet --critic --publish-date --html-file]` fetches it, encrypts the HTML to the committed key `scripts/lib/html-handoff-public-key.pem` and appends an `ingest-html-handoff` action. CI decrypts with the `HTML_HANDOFF_PRIVATE_KEY` secret, checks the page's canonical URL equals the plan's url, and runs `ingest-review-from-url.js --html-file`. A stale file the ingest would only merge into (wrong byline, fragment body) needs a `review-file-op` delete first. Rotation, trust boundary and key bootstrap (`html-handoff-key.yml`): the script's header.

Never put review text or reader contact details in a plan: the file is public.
