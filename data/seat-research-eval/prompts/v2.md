# Seat research prompt — v2 (2026-04-17)

Iteration of v1 with stronger non-obvious bar + new schema fields (bestRow, isValuePick, bestFor/worstFor).

## Changes from v1
1. **Non-obvious bar:** every section's rationale MUST include a theater-specific fact that couldn't apply to any Broadway house. Generic "center orch sweet-spot, rear orch skip" verdicts fail.
2. **bestRow field** required for every sweet-spot section — the single sweetest row within the range (not just the range).
3. **isValuePick boolean** — exactly one section per theater flagged true. The best bang-for-buck. Orthogonal to sweet-spot (can be solid tier, can be budget priced).
4. **bestFor / worstFor arrays** populated where evidence supports. Values: `musical` | `play` | `dance-heavy` | `spectacle` | `intimate-drama`.
5. **Minimum section bar** — if a section only adds what any theatergoer already knows, OMIT it. Better 3 non-obvious sections than 6 with one generic entry.

## The prompt (paste into subagent dispatch)

You are researching **{THEATER_NAME}** ({ADDRESS}, capacity {CAPACITY}, operator {OPERATOR}) to produce section-level seat guidance for broadwayscorecard.com.

## Your job
Produce `/tmp/{SLUG}-research.json` containing 3-6 section verdicts. **Every section must earn its place** — if a section is obvious (center orch = best, rear balcony = bad) without anything theater-specific to add, OMIT IT. Users already know the generics.

## The "uniquely helpful" bar (NEW in v2)

Your rationale must do at least ONE of these for every section, or the section is dropped:

1. **Name a theater-specific quirk** that couldn't apply elsewhere — specific overhang row, specific pillar, specific stage height, specific acoustic dead-spot.
2. **Reframe a non-obvious tradeoff** — e.g., "rear mezz front rows beat front orch for this show's set because..." Tradeoff must be specific to this house.
3. **Flag show-type sensitivity** — "great for musicals but rough for plays because this house's Row J sightline..." (and populate bestFor/worstFor).
4. **Call out a value play** — specific section where the price tier undersells what you actually get here.

If a section is "center orchestra is the best seats," OMIT IT. If a section is "rear orchestra has an overhang," it earns its place only if you specify Row X+ with evidence.

## Required fields (NEW: bestRow, isValuePick, bestFor, worstFor)

Every sweet-spot section MUST have:
- `bestRow`: the single sweetest row within `rowRange` (e.g. "Row I" not "Rows F-L"). If evidence doesn't identify one, drop the section — this is a precision check.

Exactly ONE section per theater MUST have:
- `isValuePick: true`: the best bang for buck. Can be ANY verdict level. Often it's a solid-tier section priced below its actual experience. Rule: this section is the answer to "what would you tell a friend with a strict budget?"

Populate where evidence supports:
- `bestFor`: array of show types this section is best for (subset of `musical`, `play`, `dance-heavy`, `spectacle`, `intimate-drama`)
- `worstFor`: array of show types to avoid this section for

Omit `bestFor`/`worstFor` if evidence doesn't distinguish.

## Source hierarchy (STRICT — unchanged from v1)

**T1 — primary (MUST hit ≥2 per section before assigning a verdict):**
- **AViewFromMySeat** — `browser_navigate` via Playwright MCP to `https://aviewfrommyseat.com/venue/{URL-ENCODED NAME}/`. Use `browser_evaluate` with `document.body.innerText` to grab per-seat user comments. WebFetch 403s — do NOT use it.
- **Reddit** — WebSearch `site:reddit.com "{THEATER_NAME}" (best OR avoid OR seats) after:2022-01-01`
- **BroadwayWorld forum** — `board.broadwayworld.com` via Playwright MCP (Bright Data times out)
- **All That Chat** — `talkinbroadway.com/forum`

**T2 — supporting:** Playbill, operator pages (Shubert/Jujamcyn/Nederlander/ATG), Wikipedia for structural facts only.

**T3 — corroboration ONLY (cannot be primary for any claim):** Seatplan, TripAdvisor, Tickpick, Headout.

## ANTI-FABRICATION RULES (strict — learned from v1 shipping fabricated claims)

1. **Never invent seat numbers.** "Pillar at Row M Seat 15" requires a source saying those exact words.
2. **Never invent row-specific geometric claims.** "Row A overhangs Orchestra Row J" — cite verbatim or drop.
3. **Never attribute language to a source that didn't use it.**
4. **Row ranges must match evidence.** If evidence supports A-B, write A-B — not A-C.
5. **bestRow must come from an explicit source reference.** If no source calls out a single best row within a range, LEAVE bestRow OUT. Don't guess based on geometry.
6. **Comparative claims need comparison.** "Beats other Broadway houses" requires evidence about other houses.
7. **Verdict follows evidence.** Sources say "conditional/avoid" → verdict is `skip`.

## Voice rules (unchanged from v1)
1. Take a side.
2. Be specific.
3. Match critic-score register.
4. Name the tradeoff.
5. 1-2 sentences per rationale, max.

## Methodology rules
- ≥8 independent data points per section
- ≥70% agreement for `sweet-spot`
- `skip` requires ≥3 specific complaints
- 2022+ recency
- Every rationale + hazard note cites ≥1 `evidenceUrl`

## Verdict budget per theater
- `sweet-spot`: 1-2 max
- `solid`: 1-3
- `skip`: 0-2
- **Exactly one** `isValuePick: true` (can be any verdict tier)

## Schema

```json
{
  "theater": "{THEATER_NAME}",
  "lastResearched": "{YYYY-MM-DD}",
  "sections": [
    {
      "name": "Orchestra Center",
      "rowRange": "F-L",
      "bestRow": "Row I",
      "verdict": "sweet-spot",
      "verdictLabel": "Our pick",
      "priceTier": "premium",
      "isValuePick": false,
      "rationale": "Center rows F-L sit past the Row A-B neck-crane and before the Row H mezz overhang bites. Row I is dead center — the one row to pick.",
      "hazards": [],
      "bestFor": ["musical", "dance-heavy"],
      "worstFor": [],
      "dataPoints": 14,
      "evidenceUrls": ["..."]
    }
  ]
}
```

Allowed values:
- `verdict`: `sweet-spot` | `solid` | `skip`
- `priceTier`: `budget` | `mid` | `premium` | `top`
- `bestFor` / `worstFor`: `musical` | `play` | `dance-heavy` | `spectacle` | `intimate-drama`
- Hazard `type`: `mezz-overhang`, `pillar`, `obstructed-view`, `side-angle`, `steep-rake`, `tight-legroom`, `distant`, `partial-stage`, `sound-dead-spot`

## Verify before reporting DONE
- Every section has `dataPoints >= 8`
- Every sweet-spot section has `bestRow` — else drop
- Exactly ONE section has `isValuePick: true`
- Every rationale passes the "uniquely helpful" bar (theater-specific quirk / reframed tradeoff / show-type sensitivity / value play)
- No generic section like "center orch is the best seats" — if you found yourself writing that, drop the section
- No fabricated seat numbers, row-specific geometric claims, or misattributed quotes
- Every rationale + hazard note traces to ≥1 `evidenceUrl`
- Verdict budgets respected
