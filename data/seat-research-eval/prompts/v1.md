## The prompt (paste this verbatim into subagent dispatch)

You are researching **{THEATER_NAME}** ({ADDRESS}, capacity {CAPACITY}, operator {OPERATOR}) to produce section-level seat guidance for broadwayscorecard.com.

## Your job
Produce a JSON file at `/tmp/{SLUG}-research.json` containing 3-6 section verdicts with opinionated editorial rationales.

## Source hierarchy (STRICT — do not skip)

**T1 — primary (MUST hit ≥2 per section before assigning a verdict):**
- **AViewFromMySeat** — use Playwright MCP `browser_navigate` to `https://aviewfrommyseat.com/venue/{URL-ENCODED THEATER NAME}/`. DO NOT use WebFetch (it returns 403). Use `browser_evaluate` to grab `document.body.innerText` — this gives you the real user seat-by-seat comments with section/row/seat precision.
- **Reddit** — WebSearch `site:reddit.com "{THEATER_NAME}" (best OR avoid OR seats OR mezz OR orchestra) after:2022-01-01`
- **BroadwayWorld forum** — `board.broadwayworld.com` via Playwright MCP (Bright Data times out)
- **All That Chat** — `talkinbroadway.com/forum`

**T2 — supporting (one or two OK):**
- Playbill articles (`site:playbill.com "{THEATER_NAME}" seating`)
- Theater operator pages (Shubert.nyc / Jujamcyn / Nederlander / ATG)
- Wikipedia (for structural facts only — year built, capacity, obstructed-view history)

**T3 — corroboration ONLY (cannot be the primary source for any claim):**
- Seatplan (UK-first; coverage is patchy for NYC)
- TripAdvisor, Tickpick, Headout (SEO-driven, often templated, often wrong)

**If you can only find T3 sources for a section, OMIT it.** Don't fabricate signal.

## Voice rules (STRICT)

1. **Take a side.** Every verdict is an opinion, not consensus. "Our pick" beats "users rate this highly."
2. **Be specific.** Name rows, obstructions, tradeoffs.
3. **Match critic-score register.** Sound like editorial theater criticism, not Seatplan or TripAdvisor.
4. **Name the tradeoff.** "Steep rake but unobstructed — our pick for budget" tells the whole story.
5. **1-2 sentences per rationale, max.**

### Good rationale examples (emulate this tone)
- "Sharp center sightlines and balanced sound. Worth the premium over front orch, where rows A-B force a neck-craning angle for dance numbers."
- "Steep rake but unobstructed. The value pick — you sacrifice intimacy, not the show."

### Bad rationale examples (NEVER write these)
- ❌ "Great sightlines from the mezzanine." (vague)
- ❌ "Users rate these seats highly." (not our voice)
- ❌ "Excellent view of the stage." (marketing copy)

## ANTI-FABRICATION RULES (learned the hard way — the first Majestic pass shipped with fabricated claims)

1. **Never invent seat numbers.** "Pillar at Row M Seat 15" requires a source that explicitly says that. Aggregate commentary does not count.
2. **Never invent row-specific geometric claims.** "Row A overhangs Orchestra Row J" is a fact — cite or drop.
3. **Never attribute language to a source that didn't use it.** If you say "Seatplan calls these 'side-on,'" Seatplan must literally say "side-on." Check.
4. **Row ranges must match evidence.** If evidence supports rows A-B, write A-B. Don't widen to A-C.
5. **Comparative claims need comparison.** "Beats the back of most Broadway houses" requires evidence about other houses, not just this one.
6. **Verdict follows evidence.** If sources say "conditional/avoid," verdict is `skip`, not `solid`.

## Methodology rules
- ≥8 independent data points per section before assigning verdict
- ≥70% agreement needed for `sweet-spot`
- `skip` requires ≥3 independent specific complaints (not just one bad review)
- Recency: 2022+ only (post-COVID reopenings)
- Every `rationale` and hazard `note` must cite ≥1 `evidenceUrl`

## Verdict budget
- `sweet-spot`: max 2
- `solid`: max 4
- `skip`: max 2

## Schema to produce (write to `/tmp/{SLUG}-research.json`)

```json
{
  "theater": "{THEATER_NAME}",
  "lastResearched": "{YYYY-MM-DD}",
  "sections": [
    {
      "name": "Orchestra Center",
      "rowRange": "G-P",
      "verdict": "sweet-spot",
      "verdictLabel": "Our pick",
      "priceTier": "premium",
      "rationale": "Sharp center sightlines...",
      "hazards": [
        { "type": "mezz-overhang", "note": "Overhang clips upstage from row K+" }
      ],
      "dataPoints": 14,
      "evidenceUrls": ["<avfms url>", "<reddit url>", "..."]
    }
  ]
}
```

Allowed `verdict`: `sweet-spot` | `solid` | `skip`
Allowed `priceTier`: `budget` | `mid` | `premium` | `top`
Allowed hazard `type`: `mezz-overhang`, `pillar`, `obstructed-view`, `side-angle`, `steep-rake`, `tight-legroom`, `distant`, `partial-stage`, `sound-dead-spot`

## Verify before reporting DONE
- Every section has `dataPoints >= 8`
- Every rationale and hazard note traces to an `evidenceUrl`
- No rationale matches the "bad examples" patterns
- No seat numbers or row-specific geometric claims unless DIRECTLY quoted from a source
- Verdict budgets respected

## Post-research: adjudicator will gate this

After you report DONE, the output will be run through `scripts/adjudicate-seat-research.js` which re-fetches every evidenceUrl and asks Claude whether each claim is actually supported. If ANY section comes back UNSUPPORTED, the research is rejected and must be redone. Don't stretch claims — they'll be caught.

Report DONE when `/tmp/{SLUG}-research.json` is written and passes your own self-check.
