# Broadway Scorecard — Codex Agent Instructions

## CLAUDE.md is the rulebook (BRO-4745, BRO-5072)
Read `CLAUDE.md` before any work: its rules apply to you in full (stack, test commands, data rules,
design system, scoring, scraping, deployment, email safety). This file holds only what is specific to
Codex. Don't copy CLAUDE.md rules here: the copies drifted (this file still listed the old T3 weight
0.35 months after `src/config/scoring.ts` moved it to 0.40). Change the rule in CLAUDE.md instead.

## Codex cloud tasks (chatgpt.com/codex): edit in place (BRO-5646)
Work in the checkout the task started in. CLAUDE.md's worktree, Linear, landing and finish-chain
steps are for Claude sessions: do not create a git worktree, another clone or a branch, and do not
push. Codex cloud builds the task's diff, and the owner's "Create PR" button, from the starting
checkout only; a change made in a side worktree shows as "no diff" and cannot be landed. After
"Create PR", `.github/workflows/codex-pr-lander.yml` tests, reviews and lands the PR, and comments
in plain English on it if it does not.
If a task does create a branch or pull request itself, name the branch `codex/<short-slug>`
(for example `codex/playbill-london-market`): the lander only picks up `codex/` branches, so a
`fix/...` or `feat/...` branch is never checked or landed.

## Codex setup
Claude's own guards (`.claude/settings.json` hooks, run through `scripts/codex/hook-adapter.js`), live
web search and sandbox network reach you via `~/.codex`, which `node scripts/codex/install.js` sets up
(idempotent; cloud bootstrap and Claude's Codex reviews run it). Codex reads `~/.codex` only at
startup: if `node scripts/codex/install.js --check` fails, install, then start a fresh `codex` run.
Claude's checklists (`/ship-check`, `/did-it-work`, `/what-else`, `/wrap-up`, ...) are your skills in
`.agents/skills`, generated by `node scripts/codex/sync-skills.js`; never edit them there, edit the
`.claude/` source and re-run the script.

## Data preflight: only when the diff needs data
- **Data-dependent** (touches `data/*.json`, `src/lib/data-core.ts`, `src/lib/engine.ts`, `src/lib/scoring.ts`, or any script that reads/writes `data/*.json`): run `npm run data:check` first. If core data files are missing, stop and report it.
- **Data-independent** (e.g. only `scripts/lib/` helpers, `tests/`, docs, CI config, nothing importing `data/`): skip `data:check` and review straight away. Missing core data is irrelevant there.

When unsure, `grep` the changed files for `data/` or `require(...data...)`; no match means data-independent.

## Codex-relevant rules CLAUDE.md doesn't spell out
- Workflows that scrape must pass both `BRIGHTDATA_TOKEN` and `SCRAPINGBEE_API_KEY` (scraping itself goes through `fetchPage()` in `scripts/lib/scraper.js`).
- Tests are `.mjs` files using the `node:test` API; Jest is not installed.
- Emailing the owner (status or a question): follow `docs/owner-email-guidelines.md`. Questions go on a DECISION NEEDED card, never "reply yes".

## Never (only the broadcast rule is hook-enforced; CLAUDE.md has the full list)
- Call `POST /broadcasts/{id}/send` or test against a Resend audience with real contacts.
- Commit review texts, PII or keys to this public repo.
- Extract metadata from URLs.
- Dispatch `vercel-deploy.yml` by hand outside an emergency.
- Mark a show `recouped: true` without a citation.
